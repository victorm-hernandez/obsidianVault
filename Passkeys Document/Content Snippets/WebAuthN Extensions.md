The Web Authentication (WebAuthn) API allows developers to use **extensions** to request optional, specialized features during registration (`navigator.credentials.create()`) and authentication (`navigator.credentials.get()`).

Here is an enumeration of the standard extensions defined in the WebAuthn Level 3 specification, their purposes, scenarios, and coding examples.

---

### 1. Credential Properties Extension (`credProps`)

**Purpose**: Allows the Relying Party (server) to discover the properties of a newly created credential. Specifically, it tells you whether the authenticator actually created a **discoverable credential** (also known as a resident key).

**Scenario**: You want to offer "username-less" login (where the user just clicks a button without typing their username). This requires a discoverable credential. Since you set `residentKey: "preferred"` during registration, the authenticator might create one, or it might fall back to a non-discoverable one if it lacks storage. You use `credProps` to find out what actually happened so you can update your database and tailor the user's future login experience.

**Coding Example** (Registration):

``` javascript

const publicKeyCredentialCreationOptions = {

  // ... standard options (challenge, rp, user, pubKeyCredParams)

  authenticatorSelection: {

    residentKey: "preferred"

  },

  extensions: {

    credProps: true // Request the property evaluation

  }

};

const credential = await navigator.credentials.create({

  publicKey: publicKeyCredentialCreationOptions

});

// Check the extension results

const extensionResults = credential.getClientExtensionResults();

if (extensionResults.credProps && extensionResults.credProps.rk) {

  console.log("A Discoverable Credential (resident key) was successfully created!");

}
```

### 2. Pseudo-Random Function Extension (`prf`)

**Purpose**: Allows a web application to derive a stable, symmetric cryptographic key from the authenticator.

**Scenario**: You are building an end-to-end encrypted application (like a web-based password manager). You need a symmetric key to encrypt the user's local vault. Instead of making the user memorize a master password, you use the `prf` extension. You provide a salt to the authenticator, and it uses the credential's internal secret to generate a secure symmetric key. If the user plugs in their YubiKey, the vault decrypts.

**Coding Example** (Authentication):

```javascript

// A secure, random 32-byte salt generated by your app

const salt = new Uint8Array(32); 

crypto.getRandomValues(salt);

const publicKeyCredentialRequestOptions = {

  // ... standard options (challenge, rpId)

  extensions: {

    prf: {

      eval: {

        first: salt // Ask the authenticator to evaluate this salt

      }

    }

  }

};

const assertion = await navigator.credentials.get({

  publicKey: publicKeyCredentialRequestOptions

});

const extensionResults = assertion.getClientExtensionResults();

if (extensionResults.prf && extensionResults.prf.results) {

  // This is your derived symmetric key! Use it to encrypt/decrypt local data.

  const derivedKey = extensionResults.prf.results.first;

}
```

### 3. Large Blob Storage Extension (`largeBlob`)

**Purpose**: Allows web applications to store opaque payloads of data directly onto the physical authenticator.

**Scenario**: You want to store a wrapped SSH key, a short user profile, or recovery codes directly on the user's hardware security key. When the user takes their security key to a brand-new computer, they can read the blob from the key to instantly restore their configuration.

**Coding Example** (Reading data during Authentication):

```javascript

const publicKeyCredentialRequestOptions = {

  // ... standard options

  extensions: {

    largeBlob: {

      read: true // Request to read the stored blob

    }

  }

};

const assertion = await navigator.credentials.get({

  publicKey: publicKeyCredentialRequestOptions

});

const extensionResults = assertion.getClientExtensionResults();

if (extensionResults.largeBlob && extensionResults.largeBlob.blob) {

  const storedData = new TextDecoder().decode(extensionResults.largeBlob.blob);

  console.log("Data retrieved from authenticator:", storedData);

}
```

### 4. FIDO AppID Extension (`appid`)

**Purpose**: Provides backwards compatibility for credentials created under the older FIDO U2F standard.

**Scenario**: Under the old U2F protocol, credentials were bound to an `AppID` (which was a full URL like `https://example.com`). Under WebAuthn, credentials are bound to an `RP ID` (a domain string like `example.com`). If you migrated your site from U2F to WebAuthn, a user with an old U2F key will fail to authenticate because the RP ID doesn't match the old AppID. This extension tells the authenticator: _"Try matching against the RP ID, but if that fails, try matching against this old AppID."_

**Coding Example** (Authentication):

```javascript

const publicKeyCredentialRequestOptions = {

  challenge: new Uint8Array([...]),

  rpId: "example.com", 

  allowCredentials: [{

    id: oldU2fCredentialId,

    type: "public-key"

  }],

  extensions: {

    appid: "https://example.com" // The legacy U2F AppID

  }

};

const assertion = await navigator.credentials.get({

  publicKey: publicKeyCredentialRequestOptions

});

const extensionResults = assertion.getClientExtensionResults();

if (extensionResults.appid) {

  console.log("User authenticated using a legacy U2F credential.");

}
```

### 5. FIDO AppID Exclusion Extension (`appidExclude`)

**Purpose**: Prevents double-registration of legacy FIDO U2F authenticators.

**Scenario**: Building on the scenario above, you have migrated to WebAuthn. A user who already registered their YubiKey under the old U2F protocol decides to click "Add Security Key" in their settings. To prevent them from registering the exact same physical key a second time (which is confusing and wastes credential storage), you pass their existing U2F credential IDs into the `excludeCredentials` list. However, because those are old U2F credentials, the authenticator won't recognize them unless you also provide the legacy AppID via this extension.

**Coding Example** (Registration):

```javascript
const publicKeyCredentialCreationOptions = {
  // ... standard options
  excludeCredentials: [{
    id: oldU2fCredentialId,
    type: "public-key"
  }],
  extensions: {
    appidExclude: "https://example.com" // Provide the old AppID so exclusions work
  }
};

try {
  const credential = await navigator.credentials.create({
    publicKey: publicKeyCredentialCreationOptions
  });
} catch (error) {
  if (error.name === "InvalidStateError") {
    console.log("The user tried to register a key they already registered via U2F!");
  }
}
```
