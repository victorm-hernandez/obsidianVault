# Interview Project Story: Securing Non-Human Identity with OWASP Agent Control Standard (ACS)

**Role:** Security Engineering Contributor  
**Project:** OWASP genAI Security Project – Agent Control Standard (ACS)  
**Core Themes:** AI Security, Non-Human Identity, AuthN/AuthZ, Standards Development, Observability

## 1. Situation (Context & Background)
The rapid enterprise adoption of AI and agentic workflows has created a massive security blind spot. AI agents operate autonomously across in-house systems, SaaS platforms, and endpoints, often making decisions and executing actions without standard runtime controls or robust identity frameworks. Enterprises need a way to inspect, trace, and instrument these agents regardless of the underlying framework. To solve this industry-wide challenge, I joined the **OWASP genAI Security Project** as a contributor, specifically focusing on the newly adopted **Agent Control Standard (ACS)**.

## 2. Task (The Challenge)
ACS aims to make AI agents trustworthy by standardizing runtime observability and control via an open-source specification. The core architecture relies on defining a strict interaction model between an "Observed Agent" and a "Guardian Agent." 

My goal within this project was to tackle the complex domain of **modern non-human identity**, contribute to the normative specification, and help build out the reference implementations. The challenge was to ensure that agent identity, tokenization, and capability negotiation were secure, vendor-neutral, and scalable for enterprise adoption.
